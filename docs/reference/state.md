# 状态与存档

Storyteller 用状态记录剧情进度：玩家状态每个玩家一份，全局状态整个服务器一份。对话进行中的进度（对话 frame 列表）与状态键分开保存，本页说明两者的存放位置、写入时机与保留规则。

## 两种状态

| | 玩家状态 | 全局状态 |
| --- | --- | --- |
| 范围 | 每个玩家一份 | 整个服务器一份 |
| 读写 | `update` / `get` / `delete` | `update global` / `get global` / `delete global` |
| 条件里 | 键名直接作为变量 | `global` 对象的属性 |
| 选择器 | `st_key` / `st_value` / `st_predicate` | 通过表达式间接访问 |

内置的全局键 `dialogIntervalTicks` 保存对话的动作间隔（游戏刻），压入对话时读取，默认 1。

## 值类型

| 类型 | `update` 写法示例 |
| --- | --- |
| 布尔 | `update done true` |
| 整数 | `update chapter 2` |
| 小数 | `update ratio 0.75` |
| 字符串 | `update name 灰松村` |

存档文件还支持列表、字符串键映射与嵌套值，`update` 命令写入的都是标量。键名不能使用 `dialogStack`、`dialogScriptChecksum`、`dialogSuspended`。

## 存档文件与保存时机

| 内容 | 文件 |
| --- | --- |
| 玩家状态 | `<世界存档>/data/storyteller/players/<玩家UUID>.nbt` |
| 全局状态 | `<世界存档>/data/storyteller/global.nbt` |
| 对话 frame 列表 | 玩家状态的一部分，保存在玩家状态文件里 |

写入时机：

- 服务器保存世界时；
- 服务器停止时；
- 玩家断线时（玩家状态随后从内存移除）。

只有发生过修改的状态才会写盘，写入先写临时文件再原子替换目标文件。全局状态在服务器启动时加载，玩家状态在玩家加入时加载。

## 对话进度与脚本校验和

对话进度（frame 列表）与脚本内容绑定。脚本表有一个内容校验和：按脚本 ID 与对话 ID 排序，把解析后的全部脚本规范化为字节流后计算 SHA-256。注释与空行不影响校验和，任何内容变化（对话 ID、动作、条件、文本、命令）都会改变校验和。

玩家状态里保存着玩家使用的脚本校验和，比较时机有两个：

- **玩家加入时**：校验和不一致就清空 frame 列表与挂起标记，写入当前校验和；一致就保留进度，对话从上次的位置继续。
- **数据包重载时**：重载前后的校验和不同，就对所有在线玩家做同样处理；一致则什么都不做。

| 场景 | 结果 |
| --- | --- |
| 脚本修改后 `/reload` | 在线玩家 frame 清空，离线玩家加入时清空 |
| 内容不变时 `/reload` | frame 保留 |
| 服务器重启，内容不变 | frame 保留，对话从上次位置继续 |
| 服务器重启，内容变化 | 玩家加入时 frame 清空 |
| 玩家断线重连，期间内容不变 | frame 保留 |

`/storyteller:reset` 立即清空执行玩家的 frame 列表、挂起标记与点击 token 允许集合，并写入当前校验和。

普通状态键（玩家与全局）与脚本版本无关，跨重载与跨重启保留。

## 注意事项

- **保持脚本 ID 稳定**：脚本 ID 来自文件路径，重命名文件或移动目录都会改变 ID，引用旧 ID 的对话与触发命令会失效，校验和变化也会清空全部玩家的进度。
- **旧状态键不会自动清理**：数据包不再使用某个键后，旧值仍留在存档里，需要时用 `delete` 清理。
- **进度清空只针对 frame 列表**：`update` 写入的状态键在脚本变化后依然保留，条件可以继续使用。
- **一个脚本变化会清空所有玩家**：校验和按整个脚本表计算，任意脚本的内容变化都会让全部玩家的对话进度重新开始。
