# 对话运行

对话在服务器上如何开始、推进与结束：frame 的压入弹出、每个游戏刻的处理规则、显示时长与间隔的计算、点击 token 的生命周期。

## frame 模型

每个玩家有一个对话 frame 列表，列表里每个 frame 是一层进行中的对话：

- 进入对话（`goto`）时压入一个 frame，记录脚本 ID、对话 ID、动作下标与节奏参数；
- 动作耗尽时自动弹出，恢复下层对话，从当初暂停的动作的下一条继续；
- `return` 弹出顶层 frame，`return all` 清空整个列表；
- 每个 frame 有自己的 `allowedContinuation`（由 `expect` 设置），只约束它自己这一层。

服务器每个游戏刻只处理顶层 frame。玩家被挂起或断线时跳过处理。

## 推进节奏

frame 的下一个动作要等到 `nextActionTick` 才开始。动作完成时，`nextActionTick` 设为当前游戏刻加上动作间隔；间隔在压入 frame 时从全局状态 `dialogIntervalTicks` 读取（默认 1），之后固定在这个 frame 上。

各动作类型的处理：

| 动作类型 | 处理 |
| --- | --- |
| 对白 | 开始时求值一次条件，为假则跳过整个动作；渲染一次文本并发送给观众，然后等待显示时长 |
| 命令 | 开始时求值一次条件；之后每个游戏刻执行一条命令，全部执行完进入下一动作；`check` 失败时序列立即终止 |
| `wait` | 等待指定游戏刻；不带数字时永久等待 |
| 分界线 | 只划分章节，不参与执行 |

对白显示时长的计算：基础 20 游戏刻，加上人物名称（含分隔符）与字面文本的长度，上限 200 游戏刻。也就是说一行普通对白显示约 1 秒出头，长句最多显示 10 秒。

## 观众

对白文本发送给观众选择器匹配到的玩家。动作行没有写观众选择器时，使用 `data/storyteller/settings.json` 中的 `defaultAudienceSelector`。设置文件在对话脚本之前加载，脚本加载时把观众选择器装填进每个动作；动作开始时直接用执行玩家的命令来源查找实体，只把匹配到的玩家作为接收者。条件求值、命令执行与 frame 推进仍由执行玩家完成。

命令动作的选择器同时决定命令的执行对象与调试文本的接收者；由 `wait` 拆分出的等待动作继承命令行的选择器。没有匹配到玩家时动作照常推进。

## 点击 token 的生命周期

对白文本的点击命令在加载脚本时注册为 token，点击执行 `run_action <token>` 查回命令序列执行。token 由选择器、命令序列与 `repeatable` 标记计算，内容相同的命令调用得到相同 token。

1. **展示**：对白动作开始时，它的点击 token 记入 frame 的 `poppedCommands`，同时加入执行玩家的允许集合，从此可以点击。观众只接收文本，不在允许集合里。
2. **消耗**：默认每个玩家对同一个 token 只能成功使用一次，之后点击报「已使用」；`repeatable` 注册的 token 不限次数。
3. **范围**：允许集合跟随 frame 变化。压入新对话时换成新 frame 的 token（新对话开始时为空），旧对白的点击随之失效；弹出对话时恢复下层 frame 的 token；弹出最后一层时保留结束对话的 token，结尾的对白文本不需要额外 `wait` 也能继续点击。
4. **重载**：脚本重载时已用记录清空；校验和变化时允许集合清空；内容变化的命令得到新 token，旧 token 不在新表里，点击报 `Unknown action token`。

独立命令动作也注册 token，但它的 token 由会话推进直接查表执行，不经过 `run_action`，不消耗已用记录。

## 条件错误与挂起

动作条件或 `check` 表达式求值抛错时，执行动作的玩家被挂起：对话停止推进，错误写入日志，调试模式开启时广播给全部玩家。挂起的恢复方式：`/st debug suspend` 切换挂起标记、`/storyteller:reset` 清空进度、脚本内容变化导致校验和变化。
